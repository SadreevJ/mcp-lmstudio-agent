# Готовый промпт для новой сессии (Этап 1)

Работаем над проектом `mcp-lmstudio-agent`.

Цель: последовательно доработать проект как инструмент локальной офлайн-разработки кода по директории проекта, без IDE, с упором на практический coding workflow, MCP, shell, память проекта и качественный brief.

Важно:
- не выдумывай API, библиотеки и поведение;
- не создавай мусорные вспомогательные файлы;
- соблюдай простую и чистую архитектуру;
- domain logic не должна зависеть от infrastructure;
- избегай преждевременных абстракций;
- используй logging, а не print;
- не добавляй скрытые side effects;
- предпочитай минимальные, точные и проверяемые изменения;
- перед выдачей результата делай self-check по архитектуре, неймингу, SRP и KISS/YAGNI.

Роли в этой сессии:
1. Архитектор
2. Application engineer
3. Infrastructure engineer
4. CLI/DX engineer
5. Reviewer

Режим работы:
- идём строго по этапам;
- за один заход выполняем только один этап;
- сначала анализ текущего кода;
- потом предлагаешь минимальный план изменений;
- потом пишешь код;
- потом короткий self-check.

Порядок этапов:
1. Усиление проектного индекса и навигации
2. Поиск по проекту как отдельная capability
3. Усиление проектной памяти
4. Улучшение briefing-механизма
5. Цикл `изменил -> проверил -> зафиксировал`
6. Git-aware контекст
7. Финальная шлифовка CLI-flow

Сейчас начинаем с Этапа 1.

Твоя задача:
- изучить текущую реализацию индексации и brief-подготовки;
- определить слабые места;
- предложить минимальный и логичный план изменений;
- перечислить конкретные файлы проекта, которые нужно менять;
- после этого реализовать изменения аккуратно и без архитектурного перегруза.

Формат ответа на этап:
1. Что сейчас есть в коде.
2. Что мешает целевой функциональности.
3. Минимальный набор изменений.
4. Какие файлы будут изменены.
5. Какие инварианты нельзя сломать.
6. Код.
7. Краткий self-check по rules.
